# صندوقُ الأدوات: كيف تدخل أداةٌ جديدةٌ إلى الحقيبة

المالك يجهّز أدواتٍ متفرّقةً بأشكالٍ مختلفة، ويضعها في مجلّدٍ على الخادم.
هذه الوثيقة تصف الطريقَ من ذلك المجلّد إلى `dokits.net`.

## الموقع

```
/mnt/user/personal/dokits-inbox/
```

على مشاركة **personal** — من الماك: `smb://192.168.70.7/personal` ثمّ `dokits-inbox`.

**لماذا `personal` لا `transfer`:** مشاركةُ `transfer` عليها
`clean-transfer.sh` مجدولاً يوميّاً **يحذف كلَّ ما مضى عليه يومان**. وضعُ الصندوق
هناك كان سيمحو أدواتِ المالك صامتةً بعد يومين. مشاركةُ `personal` لا تُنظَّف.

## الهيكل

| المجلّد | المعنى |
|---|---|
| `جديد/` | ما يضعه المالك — وهو ما يُفتَّش |
| `قيد-الدمج/` | ما بدأ العملُ عليه |
| `مدمَجة/` | ما شُحن، ومعه سجلٌّ بالتاريخ والإصدار |
| `مؤجَّلة/` | ما أُجّل، ومعه سببٌ مكتوب |
| `.inbox-state/` | حالةُ التفتيش — لا يلمسها المالك |

## التفتيش

`/mnt/user/appdata/scripts/dokits-inbox-scan.sh` مجدولٌ **كلَّ ربع ساعة** من
المصدر الوحيد `/boot/config/plugins/dynamix/nas-custom.cron` (المادّة ٨هـ).

يفعل ثلاثةَ أشياء:

1. **يجرد** المُدخَلات ويكتب `.inbox-state/INBOX.json` — يقرؤه المساعدُ فوراً في أوّل جلسة.
2. **ينبّه على تلغرام مرّةً واحدةً لكلّ جديد** — البصمةُ (`اسم|أحدثُ تعديل|عددُ الملفّات|الحجم`)
   تمنع التكرار، وتكشف التعديلَ على أداةٍ سبق أن رآها.
3. **لا يحذف شيئاً.** أقصى ما يفعله إنشاءُ مجلّدات الهيكل إن غابت (المادّة ٨ص: القاعدةُ تفعل والنموذجُ يقرأ).

> **حدٌّ صريح:** المساعدُ لا يعمل بلا استدعاء. التفتيشُ الدوريُّ يكشف ويُنبّه؛
> والدمجُ يجري في جلسةٍ يفتحها المالك. الرسالةُ على تلغرام هي الجسرُ بين الاثنين.

## صيغةُ الجرد

```json
{
  "scannedAt": 1788096810,
  "pending": 1,
  "newSinceLastScan": 1,
  "items": [
    { "name": "حاسبة-عمولة", "kind": "dir", "files": 2,
      "bytes": 142, "modified": 1788096784, "note": "الاسم: حاسبة العمولة …" }
  ]
}
```

`note` أوّلُ ٤٠٠ محرفٍ من `ملاحظة.md` أو `NOTE.md` إن وُجد بجانب الأداة.

## ماذا يجري عند الدمج

1. قراءةُ الأداة وفهمُ منطقها الوظيفيّ.
2. استخراجُ المنطق دوالَّ نقيّةً + اختباراتٌ تمرّ قبل أيّ واجهة.
3. إعادةُ بناء الواجهة على [عقد التطبيع](./normalization-contract.md).
4. بيانٌ واحدٌ في [`tools/index.ts`](../tools/index.ts) — ومنه تُشتقّ الصفحةُ
   والبحثُ والتصنيفُ وsitemap والأدواتُ ذاتُ الصلة.
5. شحنٌ، ثمّ نقلُ المصدر إلى `مدمَجة/` مع سجلٍّ.

## تحسينُ أداةٍ قائمة

يسمّي المالكُ المجلّدَ بمعرّف الأداة (`pricing`)، أو يكتب في `ملاحظة.md`:

```
تطوير: pricing
```

فيُقارَن الجديدُ بالقائم، ولا يُستبدَل منطقٌ مختبَرٌ إلّا بما هو أفضلُ منه ومُثبَتٌ باختبار.

## أمرا الفحص على الماك

**داخل الجلسة** — الأمرُ المائل:

```
/inbox
```

نسختُه في `deploy/mac/inbox-command.md`، ومكانُه `~/.claude/commands/inbox.md`.
يقرأ الجردَ، ويعرض ما وجد قبل أن يبني، ويدمج بعقد التطبيع، ثمّ ينقل المصدرَ إلى
`مدمَجة/`. ويقبل اسمَ أداةٍ بعينها: `/inbox حاسبة-عمولة`.

**من الطرفيّة** — يعمل بلا CLI:

```bash
dokits-inbox          # يعرض ما ينتظر من آخر جرد
dokits-inbox --scan   # يجبر تفتيشاً جديداً أوّلاً
dokits-inbox --open   # ويفتح تطبيق Claude
```

نسختُه في `deploy/mac/dokits-inbox`، ومكانُه `~/.local/bin/dokits-inbox`.
يطبع الأسماءَ والملاحظات، **وينسخ طلبَ الفحص إلى الحافظة** — إذ لا CLI على الجهاز،
فالجسرُ هو اللصق.

## الفحصُ الخام

```bash
ssh root@192.168.70.7 'cat /mnt/user/personal/dokits-inbox/.inbox-state/INBOX.json'
```
